# Lavoro previsto, pronto da aprire come issue

Ogni file è una issue autosufficiente: titolo, problema, approccio, criteri di
accettazione, file coinvolti e le insidie note. Si copiano e si incollano su
GitHub così come sono.

[README](../../README.md).

## In che ordine

**Prima del primo studio pilota:** la #4. È poche ore di lavoro ed evita il
guasto peggiore, quello in cui nessun messaggio parte e nessuno se ne accorge.

**Durante il pilota:** la #1, appena si conosce il gestionale dello studio. È
l'unica cosa che decide se il servizio verrà usato tutti i giorni o abbandonato
dopo tre settimane.

**Quando gli studi diventano più di uno:** #2, #3 e #5. Finché lo studio è uno,
un accesso unico e un recupero password manuale sono gestibili; a cinque
diventano un servizio di reperibilità.

**Solo con dati reali alla mano:** la #6, come spiegato nella issue stessa.
